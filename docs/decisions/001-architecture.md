# ADR 001 — Required stack and safe local defaults

- The supplied technical specification takes precedence over generic website scaffolding. Next.js SSR + a separate FastAPI service and PostgreSQL are retained. This full-stack/native project is run locally; it has not been pushed to Sites hosting, which cannot run this Python/PostgreSQL architecture unchanged. Hosting is described below, rather than shipping a disconnected static mockup.
- Shared page contract and renderer semantics are separate from platform UI. Native controls use React Native primitives instead of introducing Tamagui, Reanimated and a second styling abstraction before a verified base. Web uses native HTML DnD plus keyboard/arrow alternatives. Native uses long press, tap destination and explicit accessible move actions. Continuous finger-following gesture animation is a documented remaining enhancement.
- Supabase credentials were not supplied. The default **development-only** identity adapter uses Argon2 and signed, revocable, expiring sessions backed by the same database. Supabase Auth/JWKS/password/refresh and private Storage adapters are implemented but not claimed externally verified. Switching production on with local auth is rejected.
- FastAPI is the sole business-data authority. No direct client SQL or privileged Storage credentials. App tables have RLS enabled and no client grants/policies; the dedicated backend owner role performs operations with explicit tenant checks.
- Inventory uses transactional decrement of available stock at reservation time, row locks ordered by variant ID, and order expiration timestamps. Failed/expired/cancelled/refunded reservations return stock in the same transaction as a guarded state transition. This is the spec’s allowed transactional-decrement alternative to a separate stock_reserved column/reservations table.
- Order item snapshots and collection product ordering are stored as bounded JSONB arrays for this local MVP. They are validated and authorized at the API. A normalized item/collection relation is advisable before advanced inventory reporting and larger workloads.
- All money is integer MYR minor units. Financial totals come from stored variant/shipping prices. Checkout idempotency is serialized by buyer/key using PostgreSQL transaction advisory locks. Webhook event claims and order transitions share one transaction.
- No live provider, seller payouts or collected card data. Sandbox completion goes through the same signed-event verifier/state transition as the test webhook, and every client labels sandbox mode.
- P1/P2 blog/guestbook/social feeds, AI generation, template marketplace and domains are outside this P0 build; no decorative dead buttons advertise them.
- SSR hosting: deploy Next.js to an SSR-capable Node platform; deploy the API/worker to a managed Python container platform; use dedicated managed PostgreSQL and configured Supabase Auth/Storage. EAS preview builds provide native distribution after account setup. No remote project was created or modified.
